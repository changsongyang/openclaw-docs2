# 新手引導重新設計實作計畫

> **持續更新的文件。** 本頁面以實作層級追蹤系統管理員新手引導的重新設計，
> 並隨各階段完成而更新。最後一個階段合併後，
> 本頁面將改寫為面向使用者的新手引導指南，並加入
> 文件導覽。在此之前，本頁面刻意不納入 `docs.json`。

## 核心願景

非技術使用者輸入 `openclaw onboard`（或開啟應用程式）後，會看到
單一的對話式角色——系統管理員 OpenClaw（「custodian」僅為
內部名稱；使用者一律看到「OpenClaw」）——它會找到使用者的 AI、
使用預先告知的預設值完成所有設定，而不是提出問題；讓代理程式以可見的身分誕生時刻孵化，
之後永遠保持可聯絡，擔任系統的照護者。預設就如魔法般運作，只有一道同意界線，
且不會陷入死路。

設計原則（已決定，請勿隨意重新爭論）：

- **預先告知且可輕鬆復原的預設值**取代會阻斷流程的問題。唯一的
  硬性要求是推論能正常運作；其他一切都只是選項。
- **第零題是同意界線**：「完整存取權」（建議）代表
  探索會靜默且自動進行；「先詢問」則會在每項探索——包括 AI
  掃描、應用程式掃描及記憶來源掃描——之前，統一要求一次
  明確同意，並提供完全不執行掃描的全手動路徑。
- **以對話作為介面，並逐步提升智慧**：系統管理員介面
  在任何 AI 能運作之前便已存在（使用腳本化對話），在路由通過驗證的
  當下切換為模型驅動，並明確告知使用者。它絕不假裝具有智慧：
  在路由通過驗證前輸入自由文字時，會自然地回應「先讓我把大腦
  啟動起來」。
- **孵化是一場儀式**：使用同一個對話串、切換頭像，代理程式會自行命名
  並選擇自己的面孔。系統管理員只需說明一次層級關係：「可以向我
  詢問系統相關問題，也可以直接詢問你的代理程式——它會代為轉達。」
- **依來源劃分信任層級**：官方目錄項目可以預先選取；
  無論模型排名為何，第三方 ClawHub Skills 絕不會預先選取，
  且其標籤會註明將安裝發布者的程式碼。
- **已設定的安裝不可侵犯**：重新執行新手引導只會進行驗證。
  它絕不會重新套用設定，也絕不會重新啟動閘道服務。
- **終端機是備援方案，而不是一道問題**：當閘道可連線時，優先使用瀏覽器
  儀表板；絕不詢問「要使用終端機還是瀏覽器？」。
- **能力較弱的模型會使用精簡介面**（自動 `localModelLean`），並以
  白話說明——絕不提及工具、程式碼模式或內容視窗。

## 目前已發布的流程（階段 1–3 完成後）

在全新 macOS 安裝上執行 `openclaw onboard` 的順利流程——總共按四次 Enter：

1. 安全性注意事項 → 按一次 Enter 確認（會保留記錄；不再重複詢問）。
2. **第零題**：「我該如何設定？」——完整存取權（建議）
   或先詢問。選擇會以 `wizard.accessMode` 保留；重新執行時預設採用已儲存的
   選擇。受限模式搭配「手動設定」可在完全不執行
   掃描的情況下進入提供者選擇器，並同樣略過記憶來源掃描。
3. **探索過程展示**：偵測程式開發命令列介面、環境變數金鑰及本機執行環境；
   找到程式開發代理程式時會顯示一句俏皮話；依序即時測試候選項目，並將
   失敗項目靜默彙整成單行摘要（詳細資料位於「查看其他
   選項」之後）。第一條可用路由會以預先告知的預設值呈現，
   只需按一個按鍵即可前往完整選擇器；探索其他選項或略過時，
   都會保留可用路由。
4. 記憶匯入提議（Claude Code / Codex / Hermes）；若拒絕探索，
   則略過此步驟。
5. 僅限全新安裝：自動套用標準設定計畫
   （工作區、閘道服務、工作階段——與對話式「是」所執行的計畫相同）。
   已設定的安裝會顯示「已完成設定」，且絕不觸碰服務。
6. **應用程式建議**：由已驗證的模型比對已安裝應用程式與
   官方目錄及 ClawHub；官方頻道外掛會預先勾選，第三方 Skills
   則須主動選取並附有警告標籤。可略過；
   停用開關為 `wizard.appRecommendations`。
7. **孵化**：當閘道可連線時，會開啟（圖形介面）或顯示
   （無頭模式／SSH）瀏覽器交接的儀表板 URL，並等待控制介面
   連線——「儀表板已連線——請在瀏覽器中繼續。」若無法連線，
   或使用 `--tui`，則會開啟已預載啟動孵化訊息的終端介面，
   並由代理程式自我介紹。

遠端閘道新手引導會保留原有的對話式交接
（`handoffMode: "chat"`）；設定必須套用至遠端閘道。

## 各階段實作注意事項

### 階段 1——應用程式建議（PR #109668）

- 掃描器：`src/infra/installed-apps.ts`（不需 TCC 的 macOS 列舉；會追蹤
  以符號連結連結的 `.app` 套件）。
- 候選項目：官方目錄 + ClawHub 搜尋，整體時間上限為 20 秒，離線時會自然
  降級為僅使用目錄候選項目。目錄項目是不含頂層 `id` 的套件
  資訊清單——候選項目以解析後的外掛 ID 作為鍵值（已針對實際隨附目錄進行迴歸測試；
  曾經改用 `entry.id` 作為鍵值，導致整個目錄折疊為單一項目，
  並遺漏所有官方建議）。
- AI 比對器：在已驗證的路由上執行一次補全
  （`src/system-agent/setup-app-recommendations.ts`）；不使用人工整理的套件 ID 對照表——
  模型會排除名稱碰巧重疊的項目。輸出受解析後模型本身的
  `maxTokens` 預算限制（未傳入明確上限時，由串流層套用）。
- **供應鏈防護**：ClawHub 清單文字由發布者控制，且會進入
  比對器提示，因此清單可將自身宣傳為「建議」項目。只有官方目錄項目
  可以預先選取；ClawHub Skills 一律需要明確勾選，並標示為
  「第三方 ClawHub Skill；會安裝其發布者的程式碼」。
- 節點命令 `device.apps`（TS 節點主機，與 Android 封裝格式一致），預設
  關閉分享；閘道停用開關為 `wizard.appRecommendations`。
- 交付功能位於傳統精靈與引導式系統管理員流程中
  （`src/wizard/setup.app-recommendations.ts`）；將目標改為啟動流程尾端
  仍屬於階段 5（該服務已可接受注入式清單來源）。僅執行一次語意
  （只在接受前提供、儲存掃描結果）也會隨階段 5 的儲存區一起完成；
  目前重新執行仍會再次提議。
- 另有修正：自訂 `completeSetupInference` 提示不再沿用
  32 個權杖的驗證探測輸出上限（`SETUP_INFERENCE_TEST_MAX_TOKENS`
  僅適用於「回覆 OK」探測）。

### 階段 2——命令列介面系統管理員主幹（PR #109841）

- 在 `src/commands/onboard-guided.ts` 中重整流程；遠端閘道新手引導
  透過 `handoffMode: "chat"` 保留原有的聊天交接。
- 第零題會保存 `wizard.accessMode`（"full" | "guarded"）；重新執行時
  預設採用已儲存的選擇（接受預設值絕不會在未告知的情況下，
  將受限模式降級為完整存取權）。受限模式搭配手動設定時使用
  `listManualSetupInferenceOptions`（僅設定／資訊清單，不進行探測），並
  略過記憶來源掃描。
- 探索：靜默收集失敗項目（單行摘要；詳細資料位於
  「查看其他選項」之後）、程式開發代理程式俏皮話、預先告知的路由預設值。
  俏皮話中的工作階段數量會延後實作（目前僅使用定性描述），直到有低成本的
  工作階段計數介面為止。
- 全新安裝：`applySystemAgentSetup`（確定性的對話式
  「是」），接著透過 `launchTuiCli` 孵化，並預載啟動訊息。
  已設定的安裝（既有模型或閘道設定——精靈時間戳記無法證明任何事，
  因為設定／修復也會共用這些時間戳記）：
  僅進行驗證——不套用、不重新啟動閘道服務。套用失敗時
  會退回對話式聊天。

### 階段 3——瀏覽器優先交接（PR #110054，已合併）

- `src/commands/onboard-browser-handoff.ts` 負責純圖形工作階段
  偵測（`SSH_CONNECTION`/`SSH_TTY`；Linux 上為 `DISPLAY`/`WAYLAND_DISPLAY`）
  以及 60 秒的 GUI／300 秒的 SSH 等待。目前引導式初始設定
  僅在 macOS 上啟用交接；`--tui` 和其他平台則保留
  終端備援出口。Linux/Windows 的啟用將於後續處理。
- 儀表板連結使用與傳統完成流程相同的 `resolveAdvertisedControlUiLinks`、
  `resolveLocalControlUiProbeLinks` 和 `buildOnboardingControlUiUrl` 輔助函式。
  瀏覽器啟動使用共用的 `openUrl` 輔助函式。
- 就緒檢查會輪詢現有的 `system-presence` RPC，方式是作為**呈現已設定共用密鑰的命令列介面模式
  回環用戶端**——這是每個
  `openclaw` 命令所使用的受信任路徑。使用原始共用驗證的 Control UI 用戶端
  在 SecretRef 閘道上會遭到拒絕，並顯示 "device identity required"。連線可達性
  預先檢查會解析與等待迴圈相同的目標（及密鑰），因此
  閘門與等待絕不會在驗證方面產生分歧。只有在已連線的
  `openclaw-control-ui`/`webchat` 存在狀態資料列相較於啟動前基準是新的時，
  交接才會完成（已開啟的儀表板無法
  完成交接）。
- `gateway.controlUi.enabled: false` 會在顯示任何 URL 之前短路。
- 已針對採用相同隔離設定的閘道完成端對端驗證：列印 URL → 真實
  瀏覽器連線 → "Dashboard connected — continuing in your browser" → 無
  終端備援出口。先前因 "token mismatch" 而暫停是測試控管工具
  造成的假象——請參閱下方的測試操作手冊。

### 第 4 階段——網頁管理員介面（已合併：#110141、#110242）

- `/custodian` 頁面透過 `openclaw.chat` 搭配選項卡片元件
  （2-4 張卡片、最多一個建議選項、永遠可略過）；初始設定框架使用
  `?onboarding=1`；模型設定首次執行完成後會交接至此。
- 結構化問題是 `SystemAgentChatResult` 上型別化且可附加的 `question` 欄位
  （每個選項都有 `reply` 文字；一般文字一律獨立存在，
  供 macOS 應用程式／終端介面使用）。產生端：兩種初始設定歡迎變體，以及
  具有 2-4 個封閉選項的託管精靈選取／確認步驟——實際頻道
  精靈會將其呈現為卡片。PR1 的字串標記權宜方案已刪除。
- 工作階段所有權的範圍涵蓋閘道 URL 與所有已提供的認證資訊
  （權杖、密碼、啟動權杖、已儲存的裝置權杖——在暫時性 hello 中斷期間仍保持黏著）；
  失敗的使用者回合永遠無法重播；敏感輸入會逐字傳送，並在逐字稿中遮蔽。

### 第 5 階段——出口與啟動（已合併：#110173、#110331）

- 管理員會建立無名稱的代理程式（工具呼叫）；代理程式的啟動流程
  以自行命名開始。PR1 提供最多三個節拍的儀式（名稱 → 靈魂
  短句 → skills 問題），並將自行繪製頭像／圖像生成階梯
  （模型生成的候選項目 → 預設標記 → 保留標誌）延後處理。同一
  對話串中可更換頭像；爪印保留給管理員。雙方同意的身分會持久化兩次：
  寫入 `IDENTITY.md`/`SOUL.md`（代理程式讀取的內容），以及透過
  `openclaw agents set-identity`（頻道和 UI
  顯示的內容）。
- 建議項目（第 1 階段服務、儲存的掃描結果並採僅一次語意）會作為
  啟動檔案移除前的最後一個啟動步驟出現："minimal set
  or maximum convenience?" 啟動流程會透過
  `openclaw onboard recommendations --json` 讀取已儲存的提議（僅限不透明的安裝 ID），並在
  選擇處理完畢後確認，確保不會再次詢問。頻道
  連線按鈕會攜帶各頻道的設定操作手冊；代理程式以對話方式收集
  認證資訊，並將設定寫入轉交給管理員
  （"asking OpenClaw…" 是標準用語）。
- 自我學習是以詢問而非宣告的方式提出，並同時作為 Skills 工作坊
  的同意程序；說明 ClawHub 的版本信任、掃描、驗證與完整性
  檢查，以及發布者程式碼警告——絕不可暗示每個版本都已簽署。
- 自動出口已推出：全新安裝的設定套用會宣告出口並
  進行交接（終端介面／供閘道用戶端使用的 `open-agent`）；網頁
  會進入代理程式聊天，並預先填入 "Wake up, my friend!" 草稿。
  只有在寫入後驗證無誤時才會觸發交接。刪除後代理程式數量為零時
  提供選項（而非自動執行）仍是後續潤飾項目。

### 第 6 階段——管理員存在狀態（PR1 已合併：#110269；解說／召喚屬於 PR2）

- PR1 已推出：預設固定的 "OpenClaw" 側邊欄項目（全新設定檔；
  現有使用者保留已儲存的固定項目，並可透過 customize/More 存取）、
  將 "Ask OpenClaw" 設為 Settings 的第一個項目，以及採用一般框架的
  `/custodian` 造訪，它會要求照護者問候（不使用初始設定歡迎變體），
  並且 Exit setup 僅在初始設定模式下呈現。停駐的行內 Settings 窗格
  需要抽取共用對話檢視（後續處理）。
- 具備防 Clippy 護欄的事件反應式解說：僅針對重大或
  失敗的變更，除非被詢問，否則每次設定造訪最多一次。相同的
  事件接縫之後也會讓管理員成為驗證降級或頻道故障時的發聲者。
- 頻道：日常使用時不可見（由代理程式轉交）；可透過明確
  召喚，或在同一對話串中的代理程式離線事件發生時存取，並在平台允許時
  使用自己的名稱和爪形頭像。
- 設定期間偵測到弱模型：自動設定 `localModelLean`，且管理員
  會以直白措辭說明，並提供升級選項。
- 管理員知道自己的內部暱稱（"some folks call me the
  custodian — OpenClaw's fine"），並一律以名稱稱呼代理程式。

### 第 7 階段——韌性（建置前需要負責人決策）

原始草案——"the custodian must be reachable no matter how broken
the config is"——與儲存庫的安全性政策衝突：根目錄指南
指出，設定在結構上無效時，閘道會**拒絕啟動**，
只有 SecretRef 擁有者失敗時，才會降級為已設定但不可用的
能力。從無效設定提供任何介面屬於政策變更，
而非實作細節。以下兩種範圍請擇一：

- **選項 A（建議，符合政策）：命令列介面端自動修復。** 當
  閘道或命令列介面因已知形態的無效設定而啟動失敗時，命令列介面會提議
  執行 `openclaw doctor --fix`（或經同意後執行），接著重試一次並
  清楚回報。不變更閘道行為；管理員仍可透過
  現有的 SecretRef 降級路徑及終端存取。
- **選項 B（需要負責人明確核准及安全性審查）：閘道
  最小介面模式。** 當設定在結構上無效時，啟動一個受嚴格限制的
  介面，僅提供管理員對話和修復動作。這會改寫失敗時關閉的啟動合約，
  且在撰寫任何程式碼前，必須先定義自身的輸入保護方案。

第 4-6 階段的剩餘後續項目（已追蹤、未排程）：出口的頭像／圖像生成
階梯；macOS 應用程式對型別化 `question` 欄位的呈現；管理員的
停駐行內 Settings 窗格（需要抽取共用對話檢視）；事件反應式解說及頻道召喚／代理程式離線復原
（第 6 階段 PR2）；弱模型的自動 `localModelLean`；現有
使用者已儲存的側邊欄固定項目是否應採用 OpenClaw 項目。

## 測試與合併操作手冊（得來不易；進行第 4-6 階段前請先閱讀）

- **`OPENCLAW_STATE_DIR` 不會隔離閘道服務。**
  LaunchAgent 標籤（`ai.openclaw.gateway`）是全機器共用的：使用隔離狀態目錄進行全新安裝
  初始設定測試時，會改寫並重新啟動真實
  機器的服務（包裝函式指令碼會放入隔離目錄；清除該目錄後，下次
  服務啟動就會失敗）。完成任何全新安裝
  測試後，請從真實環境使用 `openclaw gateway install --force && openclaw gateway
restart` 還原並驗證 plist。產品後續項目：
  依狀態目錄劃分範圍的服務標籤，或由初始設定偵測外部服務。
- **安全的端對端測試控管工具**：預先在隔離設定中植入 `gateway`
  區段（讓初始設定採用已設定安裝路徑，且絕不觸碰
  服務），並在備用連接埠上使用純權杖，將 `openclaw gateway run` 作為一般前景處理程序執行。
  此測試控管工具已驗證第 3 階段迴圈，包括真實的瀏覽器連線。
- **驗證路徑依用戶端身分而異，不僅取決於認證資訊。** 存在狀態及
  其他操作員讀取使用命令列介面模式的回環用戶端，其認證資訊來自
  相同設定。權杖驗證閘道需要共用密鑰；SecretRef/none
  閘道可在沒有權杖時回退至受信任的回環驗證。識別為 Control
  UI 的瀏覽器用戶端需要裝置身分或安全情境
  回環授權。探測器若對提供
  **不同**設定的閘道進行驗證（請參閱 LaunchAgent 陷阱），會以 "token mismatch" 失敗——此
  假象曾短暫阻礙第 3 階段。
- **完成探測**：`runSetupInferenceTest` 將驗證探測限制為
  32 個輸出權杖；自訂提示詞會略過此限制，並受限於
  模型本身的 `maxTokens`。推理模型會先以隱藏推理耗用該
  預算——文字為空的回合通常表示預算已在該處耗盡。
- **代理程式合併需要完全符合最新提交的託管 CI。** 在組織負載下，繁重的 `CI` 工作流程可能
  不會因推送而排入佇列；維護者的備援方式是在 PR 分支上
  分派發布閘門：

  ```bash
  gh workflow run ci.yml --ref <branch> -f target_ref=<head-sha> -f release_gate=true -f pull_request_number=<pr>
  ```

  執行必須位於
  分支參照上，才能讓 `head_sha` 相符，而標題會變成
  `CI release gate <sha>`，這是 `scripts/verify-pr-hosted-gates.mjs`
  可接受的格式。接著照常進行 `scripts/pr` 準備／合併。

- **CI 除了重點測試外還會強制執行的閘門**：文件對應表
  （新增任何文件頁面後執行 `pnpm docs:map:gen`）、oxlint（`no-map-spread`、
  `max-lines`——拆分檔案，絕不抑制）、`check:test-types`、knip
  無用程式碼檢查（僅匯出生產環境會使用的內容；測試須透過公開 API），
  以及即時測試分片分類器
  （`test/scripts/test-live-shard.test.ts` 必須列出任何新的 `*.live.test.ts`）。

## 決策記錄

- 具備終止開關的魔法掃描，而非以同意為優先（階段 1；持久性輸出會在掃描前揭露模型與 ClawHub 的使用情形，結果備註也會再次說明）。
- 完整的垂直流程，包括節點 `device.apps` 命令（階段 1）。
- 第三方 ClawHub Skills 絕不會預先選取，並會標示為將安裝發佈者的程式碼；官方項目則可預先勾選（階段 1，已發佈的安全性設計）。
- 兩張存取卡片，而非三張；將同意置於選擇流程的最前面（階段 2）。
- 自動孵化並發出公告，而非使用會阻擋流程的按鈕（階段 2/5）。
- 瀏覽器優先：終端孵化流程是備援方案，絕不詢問「終端或瀏覽器？」（階段 3）。
- 管家會出現在頻道中（召喚 + 復原），而非僅能透過網頁／命令列介面使用（階段 6）。
- 孵化會在同一討論串中進行，並切換頭像；完成後，應用程式會轉換至一般使用者介面（階段 5）。
- 設定介面保留「設定」名稱；管家位於其中（以及側邊欄），而非取代該介面（階段 6）。
- 選項卡片受到限制：提供 2–4 個選項、恰好一個建議選項，且一律可略過；相同元件同時用於初始設定與代理程式提問工具（階段 4）。
- 「正在詢問 OpenClaw……」是標準的委派用語；靈魂可增添風格，但工具敘述應保持平實（階段 5）。
- 向使用者說明弱模型的內容刪減時，文案絕不使用「程式碼模式」、「工具」或「上下文視窗」（階段 6）。

## 已知缺口與後續工作

- LaunchAgent 標籤並非以狀態目錄為範圍（這是上述測試陷阱，也是真實存在的多執行個體產品缺口）。
- 建議的一次性語意與已儲存的掃描（階段 5）；目前重新執行時仍會再次提供。
- 瀏覽器交接僅支援 macOS；Linux／Windows 的啟用仍待完成。
- 工作階段數量的趣味說法屬於定性描述；若要提供數量，需要低成本的工作階段計數介面。
- 瀏覽器交接會進入一般儀表板；初始設定模式的管家深層連結將於階段 4 加入。
